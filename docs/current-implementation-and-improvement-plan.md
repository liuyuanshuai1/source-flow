# 当前实现与改进方案

本文件说明公开代码的工作方式和下一步计划。个人订阅清单、浏览器凭据、采集数据库、原始内容、日报及自动任务配置均留在本地，不随仓库发布。第一阶段的可靠性改动已在本地实现。

## 当前实现

- `sourceflow.collector` 是 X、小红书和 B 站的入口。Python 进程调用 BrowserAct，控制已配置的 Chrome 会话，执行页面导航和 `scripts/` 中的页内提取脚本。
- X 从账号主页和回复页读取可见帖子；小红书从作者主页读取笔记列表、再打开新笔记详情；B 站从 UP 主主页发现视频，在视频页复用播放器已生成的签名请求获取可用字幕。
- `sourceflow.db` 把来源、内容、覆盖游标、待重试项和检查记录写入本地 SQLite。每次运行有独立目录，保存各平台 JSON、`new_items.json` 和 `run.json`；摘要阶段由外部任务读取本次命令返回的文件路径。
- GitHub Trending 采集不在本仓库采集器的默认运行范围内。仓库保留一个与来源采集分开的 OpenRadar 演示应用。

## 已知边界

1. X 有滚动上限，小红书列表提取器只读取初始状态的前 20 条，B 站只读取当前可见列表。到达列表边界之前会记为 `partial`，但采集器尚不能为小红书和 B 站自动翻完长列表。
2. X 页面顺序和置顶内容、各站列表加载方式可能变化；覆盖判定仍需真实账号运行验证。旧游标升级后标记为未验证，不直接声称历史覆盖完整。
3. 待重试项会在约定时间后重新检查；无字幕视频按七天后重试，暂时性详情错误按一小时后重试。旧数据库中的无字幕记录会迁入队列。
4. `new_items.json` 只包含本次数据库实际新增或更新的记录。同一天重复运行会产生不同的运行目录。

## 改进顺序

1. 已实现每来源 `complete`、`partial`、`failed`、检查范围和停止原因；只有完整覆盖且无待重试项时推进覆盖游标。
2. 已实现稳定 ID 的待重试队列、旧无字幕记录迁移和按时间重试；较早发布但后来出现的内容可在 `since_at` 之后补入。
3. 已实现数据库确认后的 `new_items.json` 和唯一运行目录。
4. 下一步用真实账号验证边界判定，并按需补小红书、B 站列表翻页能力。
5. 逐来源验证 API 获取方式。已验证的来源可选 API；其他来源保留 Chrome 路径。暂不预建自动获取 Cookie、自动改代码和多层回退框架。

调度频率和订阅清单由使用者在本机设置；公开仓库不提供实际运行环境的配置。
